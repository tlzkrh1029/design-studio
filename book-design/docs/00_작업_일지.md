# 작업 일지

이 문서는 대화에서 나온 요청과 그에 따라 수행한 작업을 시간순으로 정리한 것입니다. 시각은 한국 시간이며, 파일이 저장된 시각과 하위 작업이 시작된 시각을 근거로 적었습니다. 요청 문구는 대화에서 확인할 수 있는 부분만 따옴표로 인용했고, 나머지는 내용을 요약했습니다.

## 1. 서점 베스트셀러 표지 수집 (9월 30일 오후)

- **요청**: 국내 서점의 베스트셀러 표지를 모아 달라는 요청이었습니다.
- **수행**: 알라딘, 예스24, 교보문고의 주간 베스트셀러 목록에서 각 50권씩 모두 150권을 골라 앞표지, 뒷표지, 책등 이미지를 내려받았습니다. 서점마다 폴더를 나누고, 순위·제목·저자·출판사·ISBN·상품 페이지·파일 이름을 담은 `도서목록.csv`를 함께 만들었습니다. 내려받은 이미지는 서점별 견본 시트를 만들어 눈으로 확인했습니다.
- **결과**: `책표지_베스트셀러_20260930.zip`(188MB, 이미지 376장). 앞표지는 150권 모두, 뒷표지는 109권, 책등은 117권에 있습니다.
- **저장소에 넣은 것**: 도서 목록과 압축 파일의 파일 목록만 넣었습니다(`bookstore_covers/`). 표지 이미지는 저작권 때문에 넣지 않았습니다.
- **자세한 문서**: [01_서점_베스트셀러_표지.md](01_서점_베스트셀러_표지.md)

## 2. 경제주간지 표지 디자인 분석 (9월 30일 18시~21시)

- **요청**: 첨부한 경제주간지 표지 모음(`주간지_표지_2026.zip`: 매경이코노미 38장, 한경비즈니스 37장)을 디자인 관점에서 분석해 달라는 요청이었습니다.
- **수행**:
  1. 학계와 실무에서 쓰는 분석 틀(시각 내용 분석, 잡지 표지 구성 관습, 시각 문법, 게슈탈트, 이텐의 색채 대비, 바르트의 이미지 수사, 파노프스키의 3단계 등)을 조합해 11개 대분류, 68개 항목(범주형 55개, 계량 지표 13개)의 코딩북을 만들었습니다.
  2. Python으로 색채감, 명도 대비, 윤곽선 밀도, 압축 복잡도, 평탄 영역, 대표색 같은 계량 지표를 75장 모두에서 계산했습니다.
  3. Claude가 표지를 한 장씩 확대해 보면서 범주형 항목을 코딩했습니다.
  4. 무작위로 고른 20장을 독립된 두 번째 코더(하위 에이전트 2개)가 다시 코딩했고, 항목별 코헨의 카파를 계산했습니다(중앙값 0.76).
  5. 하위 에이전트 2개가 보고서를 따로 검증했습니다. 하나는 보고서의 수치와 문장을 데이터로 다시 계산했고, 다른 하나는 보고서가 묘사한 표지 내용과 표본 12장의 코딩을 이미지와 대조했습니다. 검증에서 나온 수정 사항은 코딩과 보고서에 반영했습니다(`analysis/audit_changes.json`).
- **결과**: Claude 문서 「2026 경제주간지 표지 디자인 분석: 매경이코노미·한경비즈니스 75장」(본문, 코딩북, 표지별 코딩의 3개 탭, 차트 6개)과 코딩 결과 CSV.
- **자세한 문서**: [02_주간지_표지_분석.md](02_주간지_표지_분석.md)

## 3. 브리핑 표지를 잡지 표지로 교체 (9월 30일 21시~23시)

- **배경**: '크립토 브리핑 서고'는 매일 06:10에 발행되는 크립토 시장 브리핑을 날짜별로 모아 두는 페이지입니다. 그때까지는 브리핑 한 편을 책 한 권으로 보고 책 표지를 그리고 있었습니다(서고 5번째 판).
- **요청**: 서고의 표지를 "모두 잡지 표지로 교체"해 달라는 요청이었습니다.
- **수행 1 (시안 1)**: 서고 데이터베이스의 브리핑 기록 31건을 읽어 사본(`data.js`)을 만들고, 모든 호에 같은 틀(테두리, 제호, 커버라인 3줄, 하단 띠)을 쓰는 잡지형 표지 모듈을 만들었습니다. 첫 시안은 연두색 테두리 하나에 국면별 색과 수치로 그린 물건 네 종류(계단, 수조, 동전, 글자)를 썼습니다(`mz_v1.js`). 결과는 디자인 캔버스 「크립토 브리핑 표지 시안」에 올렸습니다.
- **요청**: 색과 그림을 더 다양하게 해 달라는 요청이 이어졌습니다.
- **수행 2 (시안 2)**: 배색 규칙 12종과 날짜마다 137.5°씩 도는 기준 색상으로 호마다 색이 달라지게 했고, 헤드라인의 주제와 낱말에 맞춰 44종의 그림 가운데 하나를 고르게 했습니다. 그림의 형태(계단 높이, 수조 수위 등)는 그날 기록된 수치로 정했습니다(`parts/*.js` → `mz.js`).
- **질문**: "어디서 착안한거야?"
- **답변**: 표지 설계의 착안점을 설명했습니다. 주간지 분석 결과와 연결되는 설계 근거는 [03_잡지형_표지_모듈.md](03_잡지형_표지_모듈.md)에 다시 정리했습니다.
- **결정**: "좋아. 이대로 가자!"

## 6. 1차 실험: YAML 명세와 JSON 명세 (9월 30일 23시~10월 1일 1시)

- **질문**: 디자인 지시를 YAML이나 JSON 같은 구조화된 명세로 쓰면 결과가 더 좋아지는지에 대한 질문이었습니다.
- **제안과 결정**: 명세를 쓰는 사람과 만드는 사람을 나눈 통제 실험을 제안했고, "진행하자"는 답을 받았습니다.
- **수행**: 테마마다 하위 에이전트 2개가 같은 브리프를 보고 각각 YAML과 JSON으로 명세를 썼고(6개), 다른 하위 에이전트 6개가 자기 명세만 보고 페이지를 만들었습니다. 결과는 캔버스의 실험 페이지 3개에 원래 시안, 명세, 결과 순으로 올렸습니다.
- **반응**: "YAML 명세로 만든 결과"가 좋아 보인다는 반응이었습니다.
- **자세한 문서**: [05_명세_형식_실험_1차.md](05_명세_형식_실험_1차.md)

## 8. 2차 실험: 브리프+토큰, XML 태그, 명세 없이 (10월 1일 10시~12시)

- **결정**: "좋아 진행해보자"
- **수행**:
  1. 테마마다 하위 에이전트 2개가 브리프+토큰 형식과 XML 태그 형식으로 명세를 썼습니다(6개).
  2. 하위 에이전트 6개가 자기 명세만 보고 페이지를 만들었습니다. 대조군으로 하위 에이전트 3개가 명세 없이 브리프와 원래 시안만 보고 바로 페이지를 만들었습니다.
  3. 작업자마다 임시 폴더를 따로 두어 서로의 결과를 보지 못하게 했습니다.
  4. 테마마다 평가자 2명(모두 6명)이 만든 방식을 모르는 상태로 여섯 페이지를 채점하고 순위를 매겼습니다. 여섯 페이지는 원래 시안과, 다섯 가지 방식(YAML, JSON, 브리프+토큰, XML 태그, 명세 없이)으로 만든 페이지입니다.
- **결과**: 평균 순위는 명세 없이 1.83, YAML 2.33, 브리프+토큰 3.50, JSON 3.67, XML 태그 3.67, 원래 시안 6.00이었습니다. 명세 형식 사이에는 일관된 승자가 없었고, Claude가 앞서 추천한 브리프+토큰 방식이 더 안정적이라는 예상은 이 실험에서 확인되지 않았습니다. 이 점을 그대로 보고했습니다.
- **자세한 문서**: [06_명세_형식_실험_2차.md](06_명세_형식_실험_2차.md)

## 9. 밤의 가판대 YAML 시안을 실제 서고에 적용 (10월 1일 12시 무렵)

## 11. 인계 문서 작성 (10월 2일 새벽)

- **요청**: Claude의 주간 한도가 거의 다 되어 ChatGPT와 작업을 이어 가려 한다면서, 깃헙 주소만 넘기면 충분한지, 작업지시서와 일반 지침을 따로 두는 것이 좋은지 물었습니다. 이 저장소의 목적은 하던 작업을 넘겨 AI들이 디자인을 배우고 점점 더 나은 수준으로 발전시키게 하는 것이며, 예약 작업은 넘길 필요가 없다고 밝혔습니다.
- **수행**: 저장소 맨 위에 두 파일을 두었습니다.
  - `HANDOFF.md`: 이 저장소의 목적, 읽는 순서, 지금 상태, 사용자가 고른 것, Claude가 계속 맡는 것, 결정과 이유, 남은 일, ChatGPT에 보낼 첫 메시지 예시
  - `AGENTS.md`: 언어와 문체, 데이터, 표지, 서고 페이지, 확인, 디자인 개선 절차(기준선, 가설, 사본 작업, 확인, 블라인드 평가, 사용자 결정, 기록), 저장소 규칙
- **함께 권한 것**: 사용자의 한국어 문체 지침은 요약하지 말고 원문 그대로 ChatGPT의 프로젝트 지침이나 맞춤 지침에 넣도록 했습니다.
