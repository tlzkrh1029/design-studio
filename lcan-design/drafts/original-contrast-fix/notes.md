# 원본과 명암비 보정판: lcan-design 둘째 비교

2026년 10월 29일(한국 시간)에 Claude가 만들었습니다. 비교 화면은 [index.html](index.html)이고, 같은 화면을 비공개 아티팩트 https://claude.ai/artifact/MGcT6Gxfi7gFNR3912sdx3 로도 게시했습니다. 소유자만 열 수 있는 링크입니다.

## 1. 배경과 가설

- 배경: 첫 비교([../beige-token-options/notes.md](../beige-token-options/notes.md))에서 사용자는 세 요소 모두 Lucian 원본이 베이지 안보다 낫다고 했습니다(2026-10-29 0시 46분). 그런데 원본 값은 디자인 원칙 3(글자 명암비 4.5:1)에 못 미치는 곳이 있습니다. 첫 비교에서 점검한 여섯 곳 가운데 다섯 곳이 3.37~4.20:1이었습니다.
- 가설: 원본의 모양은 그대로 두고, 글자로 쓸 때 4.5:1에 못 미치는 토큰만 밝기를 가장 적게 낮추면, 원본과 거의 같아 보이면서 원칙 3을 지킬 수 있다.

## 2. 바꾼 값

값은 [contrast-fix.css](contrast-fix.css)에 있습니다. 색상(hue)과 채도는 그대로 두고, HLS 밝기만 0.25씩 낮추면서 바탕(#F4F2EE), 카드(#FFFFFF), 보조 면(#F5F3EF) 위에서 4.5:1이 되는 첫 값을 골랐습니다. 강조색은 배지 바탕과 흰 단추 글자, 완료색은 흰 단추 글자, 위험색은 자기 색을 10% 섞은 바탕 위에서도 4.5:1이 되도록 했습니다.

나머지 토큰(바탕, 카드, 선, 본문 글자, 그림자, 그라디언트 등)과 글꼴은 원본 그대로입니다. 두 칸 모두 원본 갤러리처럼 웹 글꼴을 불러오지 않습니다.

## 3. 확인

- `shot.py`로 1440×900과 390×844에서, 모션 줄이기를 켠 경우와 끈 경우를 모두 렌더링했습니다. 가로 넘침, 콘솔 오류, 칸 밖으로 잘린 요소가 없고, 화면 둘레의 웹 글꼴 세 가지를 모두 불러왔습니다.
- 세 줄의 ‘같은 동작 보기’를 한 번씩 돌린 뒤에도 잘림과 오류가 없었고, 키보드 초점 테두리가 보였습니다.
- 글자 명암비(원본 → 보정판): 작은 설명 글자 3.37 → 5.09, 023 배지 4.20 → 4.52, 023 ‘모두 끄기’에 올렸을 때 3.54 → 4.54, 042 현재 단계 번호 4.93 → 5.30, 042 ‘시작하기’ 3.49 → 5.05, 072 ‘자세히’ 3.90 → 5.00.

## 4. 지금까지 본 것

아래는 Claude가 캡처를 보고 적은 관찰이며, 평가자의 채점은 하지 않았습니다.

- 강조색(보라)은 밝기를 1.6만 낮춰서 원본과 거의 구별되지 않습니다.
- 가장 눈에 띄게 바뀌는 곳은 완료색(초록)입니다. 042의 큰 체크와 ‘시작하기’ 단추, 023의 켜진 스위치가 더 짙은 초록이 됩니다. 흰 글자를 올린 단추가 4.5:1을 넘으려면 초록 자체가 어두워져야 하기 때문입니다.
- 작은 설명 글자는 더 진한 회색이 되지만, 크기와 굵기는 그대로여서 위계는 원본과 같습니다.

## 5. 이번 보정으로 다루지 않은 것

- 원본의 다크 값도 작은 설명 글자가 3.56~3.72:1로 기준에 못 미칩니다. 이번에는 라이트 값만 보정했습니다.
- 원본 요소 400개 가운데 242개는 흰색과 검은색이 아닌 색을 요소 코드에 직접 적어 두었습니다. 그런 색은 토큰 보정으로 바뀌지 않으므로, 요소를 들일 때 하나씩 확인해야 합니다.
- 스위치, 아이콘, 진행 막대처럼 글자가 아닌 표시의 명암비는 점검하지 않았습니다.

## 6. 사용자 결정

Claude는 고를 것 세 가지를 보였습니다. 1번은 보정판을 기본으로 쓰기, 2번은 원본을 그대로 쓰기, 3번은 초록 단추는 원본 색을 두고 그 위의 글자만 짙게 바꾸기(요소 코드를 고쳐야 함)였습니다.

- 2026년 10월 29일 10시 17분에 사용자가 1번을 골랐습니다. 2번과 3번은 고르지 않았습니다(고르지 않은 이유는 기록이 없습니다).
- 이 결정에 따라 보정판의 값을 공통 테마 [../../lcan-theme.css](../../lcan-theme.css)로 옮겼습니다. 두 파일의 값은 같습니다.
- Claude가 1번에 따르는 일로 함께 밝힌 두 가지도 진행했습니다. 작업마다 테마 파일을 두는 대신 lcan-design에 공통 테마 하나를 두고, 베이지 테마 초안(`artifact-design/lcan-theme.css`)은 지우지 않고 쓰지 않는 파일로 표시했습니다.
