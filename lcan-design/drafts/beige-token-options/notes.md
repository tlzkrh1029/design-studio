# 베이지 토큰 3안: lcan-design 첫 실험

2026년 10월 29일(한국 시간)에 Claude가 만들었습니다. 비교 화면은 [index.html](index.html)이고, 같은 화면을 비공개 아티팩트 https://claude.ai/artifact/9aF7DUrSwCad8Tf8x8XQi5 로도 게시했습니다. 소유자만 열 수 있는 링크입니다.

## 1. 요청과 가설

- 요청: 베이지 테마 파일(`artifact-design/lcan-theme.css`)에서 아직 정하지 않은 값 가운데 방향을 정해야 하는 값(강조색, 경고색 등)을 2~3가지 안으로 먼저 보여 주고, 요소 두세 개로 원본과 고친 판을 나란히 렌더링해 보여 주기로 했습니다(2026-10-29 사용자 동의).
- 가설: 요소 코드는 그대로 두고 토큰 값과 `.ux` 공통 규칙의 글꼴만 바꿔도, 요소의 색과 깊이가 베이지 스타일과 어울린다.
- 이 가설은 토큰으로 바뀌는 부분만 다룹니다. 원본 요소 400개 가운데 242개는 흰색과 검은색이 아닌 색을 요소 코드에 직접 적어 두었으므로, 그런 요소가 토큰만으로 맞지 않는다는 사실은 이미 알고 있습니다. 그래서 이번 요소는 직접 적은 색이 적은 요소로 골랐습니다.

## 3. 안

결정 1(강조와 깊이)의 세 안은 안 A를 기준으로 한 가지씩만 다릅니다.

| 안 | `--ux-accent` | `--ux-accent-soft` | `--ux-grad` | `--ux-shadow` / `--ux-shadow-strong` | 근거 |
| --- | --- | --- | --- | --- | --- |
| A 먹 강조, 평면 | #1A1916 | 먹 7% | 먹색 단색 | 없음 | 시안의 주요 버튼과 ‘발동’ 배지가 먹색이고, 시안에는 그림자가 없습니다. 옅은 강조 바탕(먹 7%)만 새로 정한 값입니다. |
| B 먹 강조, 그림자 | #1A1916 | 먹 7% | 먹색 단색 | 먹 14% / 먹 30% | A와 같고, 그림자만 원본의 진하기(.14, .30)에 먹색을 썼습니다. |
| C 보라 강조, 평면 | #4A3AA7 | 보라 12% | 보라 단색 | 없음 | 보라는 시안(대화형 분석)의 차트 선 색입니다. 옅은 바탕은 원본처럼 강조색의 12%입니다. |

결정 2(경고색)의 두 안은 다음과 같습니다. 두 칸 모두 바탕은 안 A입니다.

| 안 | 값 | 근거 | 글자 명암비(바탕 / 카드 / 보조 면) |
| --- | --- | --- | --- |
| 금색 | #866500 | 시안의 근접 막대 #9A7400을 같은 색상에서 어둡게 했습니다. | 4.89 / 5.33 / 4.52 |
| 주황 | #A05616 | 원본의 경고색 #D6731E를 같은 색상에서 어둡게 했습니다. | 4.94 / 5.38 / 4.56 |

세 안에 공통인 값은 [common.css](common.css)에 있습니다. `--ux-surface-3`은 시안의 막대 바탕 #E6E0D3이고, `--ux-mint`(#117855)는 시안의 차트 초록 #138A62를, `--ux-danger`(#B23029)는 오름 빨강 #B8322A를 글자로도 쓸 수 있게 어둡게 한 값입니다. #B8322A를 그대로 쓰면 023의 ‘모두 끄기’에 올렸을 때 글자 명암비가 4.30:1이어서, 위험색만 오름 빨강과 따로 두었습니다.

이번에 정하지 않은 값은 다크 값, 모서리와 굵기 토큰입니다. 노랑 #F4E27C를 강조색으로 쓰는 안은 만들지 않았습니다. 노랑은 시안에서 ‘오늘의 판정’과 ‘근접’처럼 시선을 모을 곳에만 쓰는 색이어서, 강조색으로 쓰면 선택 상태와 근접 상태가 같은 색이 되기 때문입니다.

## 4. 파일

| 파일 | 내용 |
| --- | --- |
| `../../base.css` | 토큰 이름과 기본값(원본 라이트 값), `.ux` 공통 규칙. 글꼴은 `--lcan-font-sans`에서 읽고, 다크 값은 두지 않았습니다. |
| `common.css`, `option-a.css`, `option-b.css`, `option-c.css`, `warn-orange.css` | 안별 값. 쌓는 순서는 `base.css`, `artifact-design/lcan-theme.css`, `common.css`, 안 파일입니다. |
| `build.py` | 원본 요소와 테마 파일로 `index.html`을 만듭니다. 칸마다 테마를 클래스로 나눠 적고, 베이지 칸에서 원본 색 토큰이 하나라도 정해지지 않으면 멈춥니다. |
| `shot.py` | 1440px와 390px에서 렌더링해 점검하고, 캡처를 `screenshots/`에 둡니다. |
| `index.html` | 비교 화면입니다. `build.py`로 다시 만들고, 직접 고치지 않습니다. |

## 5. 확인

- `shot.py`로 1440×900과 390×844에서, 모션 줄이기를 켠 경우와 끈 경우를 모두 렌더링했습니다. 웹 글꼴은 npm의 Fontsource 파일로 대신 제공했습니다.
- 네 경우 모두 가로 넘침이 없고, 콘솔 오류가 없고, 웹 글꼴 세 가지를 모두 불러왔습니다. 칸 14개에서 요소가 칸 밖으로 잘리지 않았습니다(배율은 1440px에서 0.83~1, 390px에서 0.86~0.88). 표 두 개는 390px에서 자기 상자 안에서만 옆으로 밀립니다.
- 세 줄의 ‘같은 동작 보기’를 한 번씩 돌린 뒤에도 잘림과 오류가 없었고, 키보드 초점 테두리가 보였습니다.
- 글자 명암비: 정하는 토큰이 요소 안에서 글자색으로 쓰이는 여섯 곳을 계산했습니다. 원본(라이트)은 다섯 곳이 4.5:1에 못 미치고(3.37~4.20), 세 안은 모두 4.5:1 이상입니다(가장 낮은 곳은 023의 ‘모두 끄기’에 올렸을 때 4.51).

## 6. 지금까지 본 것

아래는 Claude가 캡처를 보고 적은 관찰이며, 평가자의 채점은 아직 하지 않았습니다.

- 색과 깊이는 토큰만으로 베이지 쪽으로 바뀝니다. 바탕, 카드, 글자, 상태 색이 모두 베이지 값으로 칠해지고, 그림자는 안에 따라 없어지거나 먹색으로 바뀝니다.
- 원본 모양은 남습니다. 카드 모서리(28~30px)는 베이지 시안(10~14px)보다 훨씬 둥글고, 이 차이는 세 안에서 모두 그대로입니다. 굵기는 IBM Plex Sans KR이 700까지만 있어서 저절로 700으로 줄었습니다.
- 안 A와 안 B에서는 072의 ‘새 버전’ 알림처럼 강조색으로 칠하는 알림이 회색이 됩니다.
